# No hook or gate enforces the go build / go vet / go test loop that CLAUDE.md and the review agent both require

## Problem

The project documents a verification loop in two places and automates it in none.

## Evidence

`.claude/agents/code-reviewer.md` step 4:

    4. Run `go build ./...`, `go test ./...`, `go vet ./...`

`CLAUDE.md` lists `make test`, `make lint`, `make test-race` as the development
commands and states "All functions return errors explicitly — no panics in library
code" as a convention.

Actual automation in `.claude/settings.json`: one `PostToolUse` hook running
`gofmt -w`. No `Stop` hook, no `PostToolUse` hook running the build or the tests, no
`permissions` block. Combined with the separate findings that no CI workflow runs
tests and that `make lint` cannot fail from staticcheck, nothing at any layer —
agent, local, or CI — verifies that a change compiles and passes tests.

## Impact

An agent editing this repository can leave it in a non-compiling state and receive
no signal; the `code-reviewer` agent's checklist is advisory prose that depends on
the model choosing to follow it. The evidence base for wanting this gate is the
repo's own history: `internal/models` has never had a test file, `FetchIssueComments`
has never had a test, and the pagination error path was never exercised — three gaps
that a green-by-default workflow does nothing to surface.

## Fix

Add a `Stop` hook that runs the fast gate once per turn rather than per edit:

    {
      "hooks": {
        "PostToolUse": [
          { "matcher": "Edit|Write",
            "hooks": [{ "type": "command", "command": ".claude/hooks/gofmt.sh" }] }
        ],
        "Stop": [
          { "hooks": [{ "type": "command", "command": "go build ./... && go vet ./... && go test ./..." }] }
        ]
      }
    }

Keep it on `Stop`, not `PostToolUse` — running the full suite after every write is
slow enough that it gets disabled. The CI workflow proposed separately is the
authoritative gate; this one just shortens the feedback loop.
