# Commit-counting and most event categories are unreachable: the GraphQL client never emits those event types

## Problem

`analysis` is written against the shape of GitHub's REST Events API, but the only
producer of events is `api.FetchContributions`, which synthesizes exactly five
types. Every branch keyed on the other types is unreachable in production.

## Evidence

The complete set of `Type` values the client can produce (client.go:407-498,
617-650):

    PullRequestEvent, IssuesEvent, PullRequestReviewEvent, CreateEvent, IssueCommentEvent

`trackDetailedStats` (stats.go:90-92) dispatches on a type that is never produced:

    case "PushEvent":
        stats.CommitCount += countCommits(event.Payload)

so `countCommits` (stats.go:111-122) — including its `commits` array probe, its two
`size` type-assertion fallbacks, and its "every PushEvent is at least one commit"
fallback — can never run. `stats.CommitCount` is therefore always 0 when line 73 is
reached, making the guard `if c.TotalCommitContributions > stats.CommitCount`
unconditionally true.

Of the 24 entries in `EventCategories` (categories.go:6-31), 19 are unreachable:
DeleteEvent, ForkEvent, WatchEvent, ReleaseEvent, CommitCommentEvent, GollumEvent,
MemberEvent, PublicEvent, SponsorshipEvent, PullRequestReviewCommentEvent,
PullRequestReviewThreadEvent, RepositoryEvent, StarEvent, TeamAddEvent,
OrgBlockEvent, ProjectCardEvent, ProjectColumnEvent, ProjectEvent — plus PushEvent.

## Impact

The commit-counting logic looks load-bearing and is tested (`countCommits` has
tests), so a maintainer would reasonably believe commit counts come from event
payloads. They do not — they come entirely from
`TotalCommitContributions`. Anyone "fixing" commit counts would edit code that
never executes. The category map likewise advertises coverage the tool does not
have: `CategoryReleases` can never be non-zero, which is what makes the README's
"Commits, pull requests, issues, reviews, releases, and more" claim false (filed
separately).

## Fix

Two coherent options; pick one and be explicit:

1. **Prune to reality.** Delete the `PushEvent` case and `countCommits`, set
   `stats.CommitCount = c.TotalCommitContributions` directly, and reduce
   `EventCategories` to the five types actually produced (`CategorizeEvent` already
   defaults unknown types to `CategoryOther`).
2. **Make them reachable.** If release/fork/star tracking is intended, synthesize
   those events in `FetchContributions` from the corresponding GraphQL fields and
   keep the map.

Either way, `testutil.MakeEvent` defaulting to `PushEvent` (testutil.go:10-12)
should be changed so tests stop exercising a type the production path cannot
produce.
